第二部分，技术选型。

Stack · 技术栈

技术架构一览

前端技术

  • HTML + CSS + JavaScript（纯原生）
  • localStorage 本地持久化存储
  • Canvas 手绘饼图和条形图
  • CSS 变量系统 + 动画
  • 响应式布局 + 暗色模式

AI 工具链

  • Claude Code — AI 编程工具
  • 智谱 GLM-4.5-Air — 国产大模型
  • CC Switch — 模型供应商切换
  • MCP — 文件系统访问
  • Skill — 可复用提示词模板
前端用纯 HTML/CSS/JS，不用框架。数据用 localStorage 存储。AI 工具方面用 Claude Code 配合智谱 GLM 大模型，通过 CC Switch 管理配置。

AI Tools · 工具链

四大 AI 编程工具

🤖

Claude Code

AI 编程工具，终端启动，自然语言生成代码。配合 CLAUDE.md 定义项目规范，AI 按规范编码。

🔀

CC Switch

图形化管理 AI 模型供应商。配置 API Key、Base URL、模型名称，一键切换不同大模型。

🔌

MCP

Model Context Protocol，模型上下文协议。让 AI 访问外部系统，如文件系统 MCP 让 AI 读写本地文件。

📝

Skill

可复用的提示词模板，封装常见操作。触发特定工作流，提高 AI 编程效率和一致性。

这四个工具是本次学习的重点。Claude Code 是核心编程工具，CC Switch 管理模型配置，MCP 让 AI 能操作文件系统，Skill 是提示词模板。

Performance · 性能优化

四个性能优化要点

⚡

零网络请求

50 道题内嵌 JS 文件，不用 fetch 请求外部文件。避免 CORS 跨域问题，消除网络延迟，打开即用。

💾

localStorage 本地存储

错题、收藏、连击、积分、答题用时全存浏览器本地。毫秒级读取，无需后端，刷新不丢失。

🎬

GPU 动画加速

CSS 动画用 transform 和 opacity，不触发浏览器重排，GPU 加速渲染。避免使用 top/left 属性。

🧹

计时器防泄漏

每次进入新题目前 clearInterval 清除上一个计时器，防止多个计时器同时运行导致内存泄漏。

性能优化方面有四个要点：零网络请求、localStorage 本地存储、CSS 动画用 transform 走 GPU 加速、计时器防泄漏。这些是 AI 建议的，我查资料理解了原理。

Section · 05

踩坑经验

六个典型问题与解决方案

第五部分，踩坑经验。这部分很重要，展示了实践中遇到的真实问题。

Lessons · 踩坑经验

问题与解决

遇到的问题

  • 国内无法访问 Claude API（被墙）
  • AI 自主搜索网页死循环，耗尽 2000 万 Token
  • PowerShell 执行策略阻止脚本运行
  • 中文输入乱码
  • 环境限制导致文件写入失败
  • GLM-4-Flash 高峰期响应慢
→

解决方案

  • 改用智谱 GLM 大模型，国内 API 端点
  • 禁止 AI 自主搜索，改用人提供资料
  • 修改执行策略为 RemoteSigned
  • 设置 UTF-8 编码（chcp 65001）
  • 确认工作目录，直接用 Write 工具
  • 切换为 GLM-4.5-Air 提升速度
这是六个最典型的踩坑。最重要的是 Token 被耗光的教训——AI 自主搜索会导致死循环。解决方案是禁止 AI 自主搜索，改为人提供资料让 AI 处理。
