## 一、项目概述

### 1.1 项目背景

在 AI 编程工具快速发展的背景下，本项目旨在通过 Claude Code 等 AI 辅助开发工具，以"人做决策、AI 做执行"的模式，完成一个具有实际使用价值的面试题练习器。同时作为 AI 编程能力的实践成果展示。

### 1.2 项目目标

| 目标 | 描述 | 验收标准 |
|------|------|----------|
| 核心功能 | 题库浏览、答题、错题记录 | 50 道题可正常浏览答题 |
| 学习辅助 | 错题本、收藏、统计 | 答题数据持久化，统计准确 |
| 游戏化体验 | 贴纸动画、连击特效、积分等级 | 连对/连错特效正常触发 |
| 性能优化 | 零网络请求、本地存储 | 首屏加载 < 1 秒 |
| 开发流程 | 需求→设计→开发→测试→迭代→文档 | Git 提交记录完整 |

### 1.3 目标用户

- 正在准备 Java 面试的学生
- 希望利用碎片时间刷题的求职者
- 对 AI 编程感兴趣的学习者

### 1.4 非目标（不做的事）

- 不做用户注册登录系统
- 不做后端服务器和数据库
- 不做多人在线答题
- 不做题目内容管理系统

## 三、功能规格

### 3.1 题库模块

**功能描述：** 展示 50 道 Java 面试题，按 5 个分类组织。

**分类：**

| 分类 | 题数 | 题目来源 |
|------|------|----------|
| Java 基础 | 30 | 小林笔记、JavaGuide |
| 并发编程 | 5 | JavaGuide、二哥的 Java 之路 |
| JVM | 5 | JavaGuide、小林笔记 |
| Spring | 5 | 二哥的 Java 之路 |
| 数据库 | 5 | 小林笔记、JavaGuide |

**数据结构：**
```json
{
  "id": 1,
  "category": "Java基础",
  "question": "Java中以下哪个不是基本数据类型？",
  "options": ["int", "String", "boolean", "double"],
  "answer": "B",
  "explanation": "Java的基本数据类型有8种..."
}
```

### 3.2 答题模块

**功能描述：** 用户选择答案后，立即显示对错、解析和贴纸动画。

**交互流程：**
1. 进入答题 → 计时器开始
2. 点击选项 → 计时器停止，显示结果
3. 答对 → 弹出庆祝贴纸 + 鼓励语 + 积分增加
4. 答错 → 弹出安慰贴纸 + 鼓励语 + 积分扣除 + 加入错题本
5. 查看解析 → 点击下一题

**积分规则：**

| 行为 | 积分 |
|------|------|
| 首次答对 | +10 |
| 重复答对 | +5 |
| 连对 2 题 | 1.5 倍加成 |
| 连对 3 题+ | 2 倍加成 |
| 答错 | -3（不低于 0） |

**等级体系：**

| 等级 | 图标 | 所需积分 |
|------|------|----------|
| Java 小白 | 🌱 | 0 |
| 代码新手 | 🍃 | 50 |
| 初级开发 | ⚡ | 150 |
| 中级开发 | 🔧 | 300 |
| 高级开发 | 🚀 | 500 |
| 架构师 | 👑 | 800 |
| 技术专家 | 🏆 | 1200 |

### 3.3 错题本模块

**功能描述：** 自动记录答错的题目，答对后自动移除。

**规则：**
- 答错自动加入错题本
- 在错题本中答对后自动移除
- 数据存储在 localStorage，刷新不丢失

### 3.4 统计模块

**功能描述：** 展示答题数据的可视化分析。

**展示内容：**
- 总答题数、正确数、正确率
- 各分类正确率饼图
- 答题用时分布条形图
- 当前积分和等级进度
- 积分规则说明

### 3.5 特效模块

**连对特效：**
- 连对 3 题：撒花动画（20 片彩色碎片飘落）+ 特殊庆祝贴纸
- 每 3 的倍数（6、9、12...）重复触发

**连错特效：**
- 连错 3 题：全屏变灰遮罩 + 页面抖动 + 警告文字
- 特效结束后连错计数重置

## 四、技术方案

### 4.1 技术选型

| 层面 | 选型 | 理由 |
|------|------|------|
| 前端框架 | 无框架，纯 HTML/CSS/JS | 零依赖，学习成本低，加载快 |
| 数据存储 | localStorage | 无需后端，毫秒级读取 |
| 题库数据 | 内嵌 JS 文件 | 避免 CORS 问题，零网络请求 |
| 图表渲染 | 原生 CSS + Canvas | 不引入第三方图表库 |
| AI 开发工具 | Claude Code + GLM | 国内可用，有免费额度 |
| 版本管理 | Git + GitHub | 标准化开发流程 |

### 4.2 性能设计

| 指标 | 目标 | 实现方式 |
|------|------|----------|
| 首屏加载 | < 1 秒 | 零网络请求，数据内嵌 |
| 动画帧率 | 60fps | 使用 transform/opacity，GPU 加速 |
| 内存占用 | 无泄漏 | 计时器 clearInterval，DOM 及时清理 |
| 本地存储 | < 100KB | 只存必要数据（错题ID、积分、用时） |

### 4.3 目录结构

```
interview-quiz/
├── index.html          # 页面骨架
├── css/
│   └── style.css       # 全部样式和动画
├── js/
│   └── app.js          # 全部业务逻辑
├── data/
│   └── questions.json  # 题库数据（备份）
├── images/             # 贴纸和 logo 图片
├── defense/            # 答辩演示文稿
├── docs/
│   └── PRD.md          # 本文档
├── CLAUDE.md           # AI 开发规范
├── README.md           # 项目文档
└── 答辩讲稿.md          # 答辩演讲稿
```

## 六、风险与限制

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| localStorage 容量限制（5-10MB） | 题目过多可能超出 | 当前 50 题远未达到上限 |
| 题库数据硬编码 | 扩展需改代码 | 后续可改为 fetch 加载 JSON |
| 无后端 | 数据不跨设备 | 设计取舍，后续可加后端 |
| AI 生成代码质量 | 可能引入 bug | 人工验证 + 测试 |
